# Public-sharing guide

Publish explanations written from scratch, synthetic datasets, generic diagrams and links to public documentation.

Before committing:
- Remove employer, client and colleague names, internal project acronyms and system identifiers.
- Exclude internal URLs, repository paths, tickets, screenshots, job IDs, schedules and infrastructure details.
- Never publish real records, schema exports, business rules, credentials, tokens or connection strings.
- Do not copy workplace code, generated output, configuration or internal training materials.
- Use invented entities such as customers and orders; use locally created sample data.
- Clearly label exercises, assumptions and unverified ideas.
- Review the staged diff, including notebook outputs and metadata.

Code generation notes may explain the general idea behind a tool such as cgen. Do not publish internal commands, templates or implementation details.

The ignore file is a convenience, not a security control. It does not remove files already tracked by Git.
